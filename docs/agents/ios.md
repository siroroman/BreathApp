# iOS

## Layout

| Path | What |
|---|---|
| `project.yml` | XcodeGen spec, the only source of truth for the Xcode project. `Breathnest.xcodeproj` is generated by `make gen` and git-ignored: never edit or commit it. |
| `App/Breathnest/` | App target: SwiftUI views, ticker, Core Haptics adapter, screen-awake and scene-phase handling. |
| `App/BreathnestTests/` | App unit tests (run on the simulator). |
| `BreathnestKit/` | Local Swift package, Foundation only. Domain logic: see [ADR 0001](../adr/0001-domain-logic-in-a-ui-free-swift-package.md). It also holds the protocols of the seams to the system. |

Planned, each created by its own ticket ([ADR 0002](../adr/0002-app-architecture.md)): `BreathnestUI`, a second local package (SwiftUI and Observation, depends on the Kit) with the ViewModels and drawing shared by iPhone and Watch, created before #29; `BreathnestKitTesting`, a second product of the Kit with the fakes of the seams, for tests and previews only; the Watch target (#40).

## Architecture

MVVM over the Kit, decided in [ADR 0002](../adr/0002-app-architecture.md). Read it before touching a screen, a ViewModel or a seam. In short:

- The Kit is the model. A `@MainActor` `@Observable` `<Screen>ViewModel` serves one screen with state or side effects. A view reads it and calls its methods, and holds no I/O or logic.
- A ViewModel imports no view type and holds no text for the user: it exposes values and small enums, the view builds the text from the String Catalog.
- The protocols of the seams (ticker, haptics, screen awake, scene phase, notifications, stored settings) live in the Kit, the adapters in the app. Dependencies come through `init`, from one composition root in `BreathnestApp`. No singleton.
- The Session ViewModel owns one `Task` that reads the ticker and is cancelled on Pause, Stop, completion and `deinit`.
- One root navigation model on the iPhone, so a notification opens an Exercise detail the same way a tap on a row does.

Product name Breathnest, bundle ID `com.siroroman.breathnest`, iPhone only (`TARGETED_DEVICE_FAMILY: 1`), deployment target iOS 26.0, Swift 6 language mode. Add a file under `App/` or `BreathnestKit/` and run `make gen` (the build targets do it); a new target, setting or package goes into `project.yml`.

## Simulator per worktree

`scripts/simulator.sh` owns the simulator, the Makefile calls it.

- The main checkout uses a simulator named **`Breathnest`** (iPhone 17 Pro, iOS 26.2). It is created on first use.
- Every linked worktree gets its own named **`Breathnest-<worktree folder>`**, created the same way, so parallel sessions never fight over one running device. It is created with `simctl create`, not `simctl clone`: a clone needs its source shut down, which would stop the simulator another session is running.
- `make run` boots this checkout's simulator; `scripts/simulator.sh` prints its UDID. Always pass the UDID, never `booted`, because several simulators may be running.
- Delete a worktree's simulator together with its worktree: `xcrun simctl delete "Breathnest-<folder>"`.
- To test on another OS version, change `RUNTIME` in `scripts/simulator.sh`, not the Makefile.

## Supported Xcode and runtime

Xcode 26 or later (last run with Xcode 27.0). The Simulator runtime stays pinned to **iOS 26.2** (`RUNTIME` in `scripts/simulator.sh`), also when a newer runtime is installed: the deployment target is iOS 26.0, and one runtime means the same OS on every machine and in CI. The CI job `Build, app tests, lint` runs on the `macos-26` image with Xcode 26.6 (`CI_XCODE_VERSION` in `tools.env`, selected by its `Select Xcode` step) and the runtime above, which the image has installed; its `Toolchain` step prints the version and the runtimes. Details: [commands](commands.md) (CI). Change the pin only in its own pull request: edit `RUNTIME`, the iOS version named in this file and in the header of the script, and make sure the runtime is installed (Xcode, Settings, Components).

## Conventions

The ones marked **checked** fail `make lint` ([commands](commands.md)): SwiftLint with `.swiftlint.yml` (tests are not linted) and `scripts/check-architecture.sh`. The rest are reviewed.

- Logic goes into `BreathnestKit` first, with a test. The app only draws it and talks to the system. If a type needs `UIKit`, `CoreHaptics` or `UserNotifications`, it belongs in the app target; SwiftUI code shared with the Watch belongs in `BreathnestUI` once that package exists, SwiftUI used on one platform only in its app target. **Checked:** the Kit imports only Foundation, Synchronization and Swift.
- SwiftUI with `@Observable` models, no Combine, no `ObservableObject`. Follow the `swiftui-expert-skill` for state, lists and Liquid Glass. **Checked:** no `import Combine`, no `ObservableObject`.
- Swift Concurrency: `async`/`await` and actors, no completion handlers or `DispatchQueue`. UI types are `@MainActor`. Follow the `swift-concurrency-pro` skill. Code in the Kit is `Sendable` value types where it can be. **Checked:** no `DispatchQueue`, no `completion`, `completionHandler`, `handler` or `callback` closure parameter, no force unwrap or `try!` outside tests.
- Time comes from an injected `Clock`, never `Date()` or `Task.sleep` called directly in logic (see [testing](testing.md)). **Checked** in the Kit; the app may create the `ContinuousClock` it injects.
- User-visible text lives in the String Catalog, not in the Kit and not as string literals in logic. Reviewed only: a linter cannot tell such a literal from an identifier.
- Use the glossary terms in type and test names (`Exercise`, `Pattern`, `Phase`, `Cycle`, `Session`, `Breath level`).
- No third-party dependencies without a decision recorded in an ADR. **Checked:** `scripts/check-architecture.sh` fails on a package in `Package.swift` or `project.yml`; add the ADR first, then the exception to the script.
